      Let's Encrypt

      For host names that already point at this server. Add alternatives separated by commas, such as mail.example.org, imap.example.org: each gets its own certificate, which mail apps can't tell apart from one naming them all.       A certificate chain and its unencrypted private key, in PEM. It's filed under the certificate's first name and served to clients asking for any name it covers. Uploaded certificates aren't renewed: upload a new one before it expires.

                Read-only. Switching storage does not move queued mail, so it is set in the config file and applied on restart.
                The shipped configuration has this off, and it was measured: draining the same 12,000-message queue gave 137/s with this off and 87/s with it on. Keeping the copy costs roughly a third of delivery throughput, on every delivery. Turn it on only if you may roll this server back to a build older than the content-digest change (2026-08-08): an older build reads that copy, and without it would treat a re-sent message as a conflict and refuse it.                 Allow and deny rules
                
                    
                
                        
                Inbound rules cover clients connecting here and mail from outside. Outbound rules cover where mail is going. An address or network matches the client or the destination mail server; a domain or mail address matches the sender or the recipient. Allow beats deny, and never skips virus or spam scanning. An allow rule on an address or network for all protocols also means it's never limited or blocked: add your own address and monitoring.
